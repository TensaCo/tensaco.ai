# tensaco.ai

Current state and open items: [STATUS.md](STATUS.md).

The websites of **TensaCo Inc.** and its companies. Each company presents as its own product and brand; they share only
infrastructure (Cloudflare Workers, one D1 subscriber database).

| app | URL | what |
|---|---|---|
| `apps/tensaco` | https://tensaco.ai (www → apex) | the parent company: mission, values, companies, investors, updates, careers |
| `apps/account` | https://account.tensaco.ai | TensaCo accounts: sign-in/sign-up, password reset, the customer portal and staff views |
| `apps/phaser` | https://phaser.tensaco.ai | PHASER, the optical neural accelerator: launch page, blog, subscribe |
| `apps/tensorcode-alias` | https://tensorcode.tensaco.ai | 301 → https://tensorcode.dev (TensorCode's site lives in [TensaCo/tensacode](https://github.com/TensaCo/tensacode)) |
| `packages/db` | | Drizzle schema for D1 `tensaco-subscribers` (every table), and the `db()` client |
| `packages/subscribe` | `/api/subscribe` on every site | shared email-capture handler |
| `packages/email` | | transactional email: Resend over fetch, templates, the `email_log` record |
| `migrations/` | | SQL migrations generated by Drizzle Kit from `packages/db/schema.ts` |

## Develop and deploy

```bash
cd apps/phaser          # or apps/tensaco, apps/account
npm install
npm run dev             # Next.js dev server (pages only; /api needs the Worker)
npm run preview         # build + wrangler dev: pages and /api/subscribe against a local D1
npm run deploy          # build + wrangler deploy (Cloudflare account jacobfv123@gmail.com)
```

Pushing to `main` deploys whichever apps changed (`.github/workflows/deploy.yml`; needs the `CLOUDFLARE_API_TOKEN`
repository secret).

First local run of the API: `npx wrangler d1 migrations apply tensaco-subscribers --local` in the app folder, and
`npm run env:dev` at the root (below). Run the account console locally with `npm run preview` in `apps/account`
(http://localhost:8788).

## Environment and secrets

`.env.example` (committed) lists the settings. The real values live in `.env.local` (development) and `.env.prod`
(production); both are gitignored, as are the generated `apps/*/.dev.vars`.

- `npm run env:dev` writes `apps/account/.dev.vars` and `apps/tensaco/.dev.vars` from `.env.local` for `wrangler dev`
  (host-only cookie; staff notifications go to Resend's test inbox `delivered+staff@resend.dev` unless `STAFF_EMAIL` is
  set in `.env.local`).
- Production: `RESEND_API_KEY` is a Worker secret on `tensaco-account` and `tensaco-site`. To rotate it, update
  `.env.prod`, then in each of `apps/account` and `apps/tensaco`:
  `grep '^RESEND_API_KEY=' ../../.env.prod | cut -d= -f2- | tr -d '\n' | npx wrangler secret put RESEND_API_KEY`
  (and `gh secret set RESEND_API_KEY -R TensaCo/tensaco.ai`). The non-secret settings (`EMAIL_FROM`, `EMAIL_REPLY_TO`,
  `STAFF_EMAIL`, `ACCOUNT_URL`, `SITE_URL`, `COOKIE_DOMAIN`) are `vars` in each app's `wrangler.jsonc`.
- Wrangler needs `CLOUDFLARE_ACCOUNT_ID=20d4becc35c40a0bbfb8803a525aaae1` when the login can see several accounts.

## Accounts and the customer portal (account.tensaco.ai)

`apps/account` is the TensaCo account console: its own Next.js static export and Worker (`tensaco-account`, custom
domain `account.tensaco.ai`), sharing D1 `tensaco-subscribers` and R2 `tensaco-careers` with tensaco.ai.

- **Sign-in and sign-up** at `/login/` and `/signup/`. Passwords are PBKDF2-SHA256 with a per-user salt. The session is
  a random token in the HttpOnly cookie `tc_session` (`Domain=.tensaco.ai`, Secure, SameSite=Lax; only its SHA-256 is
  stored). A second, non-HttpOnly cookie `tensaco_signed_in=1` (same domain, no secret) lets the static tensaco.ai
  header show "My account" instead of "Sign in"; logout clears both.
- **Email verification**: sign-up emails a single-use link (7 days) to `/verify/`. Unverified accounts can sign in but
  see a banner with a resend button.
- **Password reset**: `/forgot/` emails a single-use link (1 hour) to `/reset/`; setting a new password signs out
  every session and sends a "password changed" notice. Signed-in users change their password at `/security/`.
- **Portal**: overview, support conversations, service requests (PHASER compute/research, TensorCode
  deployment/training), job applications, profile and email preferences. Customers see only their own records.
- **Staff** (`users.role = 'staff'`) see and answer every conversation, review every service request, see every job
  application (details, résumé download, status), and the customer directory at `/staff/customers/`.
- tensaco.ai's old `/login/`, `/signup/` and `/account/*` URLs 301 to account.tensaco.ai (`/account/x` → `/x`).
- API: `apps/account/worker/` (`auth.ts`, `portal.ts`).

To make an account staff, sign up at https://account.tensaco.ai/signup/, then:

```bash
cd apps/account && npx wrangler d1 execute tensaco-subscribers --remote --command "UPDATE users SET role = 'staff' WHERE email = 'you@example.com'"
```

## Email (Resend)

Transactional email is sent through Resend from `no-reply@tensaco.ai` (domain verified in Resend), replies to
`hello@tensaco.ai`. Code: `packages/email` (plain HTML + text templates in TensaCo navy/white; no images, tracking
pixels or link rewriting). Every send is recorded in D1 `email_log` with Resend's id or the error.

| email | to | when | preference |
|---|---|---|---|
| verify email | the user | sign-up, "Resend email" | always |
| password reset link, password changed | the user | `/forgot/`, reset, change | always |
| reply to your conversation | the customer | staff reply | "Updates on my account activity" |
| service request updated | the customer | staff changes status or note | same |
| application updated | the applicant | staff changes status | same (if they have an account) |
| application received | the applicant | `/api/careers/apply` on tensaco.ai | always |
| staff notifications | `STAFF_EMAIL` (hello@tensaco.ai) | new conversation, customer reply, new service request, new application | — |

```bash
cd apps/account && npx wrangler d1 execute tensaco-subscribers --remote --command "SELECT created_at, kind, \"to\", provider_id, error FROM email_log ORDER BY id DESC LIMIT 20"
curl -s -H "Authorization: Bearer $RESEND_API_KEY" https://api.resend.com/emails/<provider_id>   # delivery status
```

## Careers pipeline

Postings are `apps/tensaco/src/data/jobs.ts`. Applications go to D1 `applications`; résumés to R2 bucket
`tensaco-careers` (key in `applications.resume_key`).

```bash
cd apps/tensaco
npx wrangler d1 execute tensaco-subscribers --remote --command "SELECT id, job_title, name, email, resume_key, created_at FROM applications ORDER BY created_at DESC"
npx wrangler r2 object get tensaco-careers/<resume_key> --remote --file resume.pdf
```

Staff review applications (details, résumé, status) at https://account.tensaco.ai/applications/; a status change
emails the applicant. Each application also emails the applicant a confirmation and notifies `STAFF_EMAIL`.

## Subscribers

```bash
npx wrangler d1 execute tensaco-subscribers --remote --command "SELECT email, arm, source, created_at FROM subscribers WHERE status = 'subscribed' ORDER BY created_at"
```

## Investors page data

Commercial figures (LOIs, design partners, pilots, revenue, pipeline, milestones) are edited by hand in
`apps/tensaco/src/data/traction.ts`. Adoption figures (PyPI/npm downloads, GitHub stars) are fetched at build time by
`apps/tensaco/scripts/traction.mjs`.

## Blog posts (PHASER)

Markdown/MDX in `apps/phaser/content/posts/`. Front matter: `title`, `date`, `summary`, optional `hero`, and `source`
(the original URL when a post is copied from elsewhere; it becomes the canonical URL and the "copied from" line).
MDX components are not executed; supported ones are listed in `EMBEDS` in `src/lib/posts.ts`.
